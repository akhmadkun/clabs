LAB-007 - OSPF INTERFACE TYPES & ADJACENCY
STEP-BY-STEP SOLUTION GUIDE FOR JUNIOR ENGINEERS
Source: Junos OS OSPF User Guide, Chapter 3 and Chapter 4 DR election sections.

1. PRE-FLIGHT
Stop other OSPF labs that reuse this VLAN/IP space. Never remove or recreate br-univ.
Check on R1/R2/R3:
  show interfaces terse
  show configuration protocols ospf
  show ospf neighbor
  show ospf interface
  show route protocol ospf
If baseline is unhealthy, repair it before continuing. A feature lab should not start with broken prerequisites.

2. READ THE BROADCAST SEGMENT
VLAN 12 is a shared Ethernet LAN with three routers. OSPF elects a DR and BDR.
Run:
  run show ospf interface eth1.12 detail
  run show ospf neighbor detail
  run show ospf database network
Record DR/BDR router IDs and neighbor states. On broadcast networks, two DROther routers can remain 2-Way with each other; Full adjacency is normally formed with the DR and BDR.

3. CONTROL ELECTION
Example configuration commands:
  set protocols ospf area 0.0.0.0 interface eth1.12 priority 200
  set protocols ospf area 0.0.0.0 interface eth1.12 priority 100
  set protocols ospf area 0.0.0.0 interface eth1.12 priority 0
The baseline should use default priorities. Apply 200 on R1, 100 on R2, and 0 on R3. On each:
  commit check
  commit
Priority 0 makes a router ineligible for DR/BDR. OSPF DR election is non-preemptive; a higher priority does not automatically displace an existing DR. Cause a controlled new election using a planned interface/OSPF restart sequence in the lab, without touching the host bridge. Verify:
  run show ospf interface eth1.12 detail
  run show ospf neighbor
Avoid disrupting unrelated labs or management interfaces.

4. CHANGE VLAN 13 NETWORK TYPE
On both R1 and R3, inspect:
  run show ospf interface eth1.13 detail
Expected point-to-point configuration:
  set protocols ospf area 0.0.0.1 interface eth1.13 interface-type p2p
For the broadcast test, change both ends consistently:
  delete protocols ospf area 0.0.0.1 interface eth1.13 interface-type
  set protocols ospf area 0.0.0.1 interface eth1.13 interface-type broadcast
  commit check
  commit
If syntax differs on this cRPD release, inspect the CLI with `set protocols ospf area 0.0.0.1 interface eth1.13 ?`.
Do not leave one side p2p and the other broadcast. Record election behavior, then restore both ends:
  delete protocols ospf area 0.0.0.1 interface eth1.13 interface-type
  set protocols ospf area 0.0.0.1 interface eth1.13 interface-type p2p
  commit check
  commit
Verify Full and confirm no DR/BDR election is used in p2p mode.

5. PASSIVE LOOPBACK
On R3:
  set protocols ospf area 0.0.0.1 interface lo0.0 passive
  commit check
  commit
Verify:
  run show ospf interface
  run show route 10.1.1.3/32 exact
On R1:
  run show route 10.1.1.3/32 exact
  run show ospf route
The loopback should be advertised, but should not form an adjacency.

6. FINAL RECOVERY
Restore VLAN 12 to broadcast, VLAN 13 to p2p, and retain the passive loopback as required by the final criteria.
Run:
  run show ospf neighbor
  run show ospf interface
  run show ospf database router
  run show ospf database network
  run show route protocol ospf
Confirm routing and neighbor behavior, not just configuration presence.

7. TROUBLESHOOTING
- No neighbors: check VLAN tagging, IP/subnet, area, interface state, MTU, authentication and timers.
- 2-Way on broadcast: check whether both routers are DROther before calling it a fault.
- No DR/BDR on p2p: expected.
- Unexpected election: check priority, router ID and whether a fresh election occurred.
- Missing route: inspect LSDB, OSPF route calculation and active RIB route separately.
- Do not add static routes to hide OSPF issues.

PLATFORM NOTE
This guide follows the general Junos OS guide. Exact syntax and behavior must be validated on xzjt/crpd:25.2R1-S1.4. If the required feature is unsupported in cRPD, use vJunos-router for that particular exercise.
