POC-001 — SOLUTION GUIDE
True VM-Series AE/LACP + Nexus vPC
===================================

AUDIENCE
--------
Junior engineer.

LAB GOAL
--------
Build this end-to-end path:

                 vPC DOMAIN 10
        N9K-01 ================= N9K-02
          ||         Po100         ||
          ||                      ||
       Po20/vPC20              Po20/vPC20
          ||                      ||
        PA e1/1                PA e1/2
             \                  /
              \      AE1       /
               +--------------+
                 INSIDE L3

        Po21/vPC21              Po21/vPC21
          ||                      ||
        PA e1/3                PA e1/4
             \                  /
              \      AE2       /
               +--------------+
                 OUTSIDE L3

Traffic:
  MT-INSIDE -> AE1 -> PA routing/security policy -> AE2 -> MT-OUTSIDE

This is a standalone PA PoC. No Palo Alto HA is included yet.

================================================================
0. IMPORTANT: WHAT IS OFFICIAL AND WHAT IS LAB DESIGN
================================================================

Official Palo Alto behavior used in this lab:
- VM-Series link aggregation was introduced in PAN-OS 11.1.0.
- PAN-OS 11.2 supports Aggregate Ethernet groups and LACP.
- An AE group can contain multiple Ethernet members.
- LACP can be Active or Passive.
- Both LACP peers must not be Passive.
- LACP Fast sends queries every second.
- Fast Failover can reduce failover detection to within one second.
- AE interfaces can be Layer 3.

Official Cisco behavior used in this lab:
- vPC lets one downstream device connect to both Nexus peers as one logical
  port-channel.
- The downstream port-channel gets the same vPC number on both peers.
- vPC requires the vPC feature, peer-link, and peer-keepalive.
- LACP can be used on vPC port-channels.

Lab-specific choices:
- vPC domain = 10
- peer-link = Po100
- VLAN 100 = INSIDE
- VLAN 200 = OUTSIDE
- vPC 20 = PA AE1
- vPC 21 = PA AE2
- vPC 30 = MT-INSIDE
- vPC 40 = MT-OUTSIDE
- management subnet = 172.30.30.0/24
- data subnets = 10.100.100.0/24 and 10.200.200.0/24

13. CREATE AE1 — INSIDE
================================================================

GUI:

  Network
    > Interfaces
      > Ethernet
        > Add Aggregate Group

Configure:

  Interface Name: ae1
  Interface Type: Layer3

Layer 3 settings:

  Virtual Router: VR-POC
  Security Zone: INSIDE
  IPv4 Address: 10.100.100.1/24

LACP settings:

  Enable LACP: yes
  Mode: Active
  Transmission Rate: Fast
  Max Interfaces: 2

Optional:
  Fast Failover = enabled for the failure test

WHY ACTIVE?
Palo Alto recommends one peer be Active and the other Passive. Active is used
here so the PA initiates LACP. The Nexus side is also configured as Active;
Active/Active is valid. Do not configure Passive/Passive.

32. TROUBLESHOOTING — PA AE DOWN
================================================================

Check the PA:

  show interface ae1
  show lacp aggregate-ethernet ae1

Check the PA member assignments in:

  Network > Interfaces > Ethernet

Confirm:
  ethernet1/1 -> ae1
  ethernet1/2 -> ae1

Then check Nexus:

  show port-channel summary
  show lacp neighbor
  show vpc brief

Common causes:
- PA physical port not assigned to AE.
- LACP disabled on PA.
- Nexus physical interfaces not in the same Po.
- vPC IDs differ between peers.
- vPC peer-link is down.
- one side is Passive and the other is also Passive.

34. IMPORTANT VPC CONCEPT
================================================================

The two Nexus peers are separate switches, but vPC presents them to the
PA downstream device as one logical port-channel system.

For AE1:

  PA ethernet1/1 ---- N9K-01
  PA ethernet1/2 ---- N9K-02
                \\    /
                 vPC20

For AE2:

  PA ethernet1/3 ---- N9K-01
  PA ethernet1/4 ---- N9K-02
                \\    /
                 vPC21

That is why one PA AE can contain members physically connected to two
separate Nexus chassis.

================================================================
35. IMPORTANT AE CONCEPT
================================================================

An AE interface is the logical interface.

Example:

  ae1
   |
   +-- ethernet1/1
   +-- ethernet1/2

AE1 owns:
- the IP address
- the zone
- the virtual router association
- LACP state

The member ports do not each get their own routed IP address.

================================================================
36. IMPORTANT FAILURE CONCEPT
================================================================

Normal:

  AE1
  | \
  |  \
 N9K1 N9K2
  |      |
  +-- LACP --+

One member fails:

  AE1
  | X
  |   \
 N9K1  N9K2
        |
      ACTIVE

The logical AE stays up as long as the remaining member is operational.

This is one of the main reasons to use AE/LACP.
