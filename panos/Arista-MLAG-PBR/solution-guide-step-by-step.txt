POC-001 — STEP-BY-STEP CONFIGURATION GUIDE
Palo Alto + Arista MLAG + LACP + Selective PBR

Lab version
-----------
Arista cEOS: 4.35.0F
Palo Alto VM-Series / PAN-OS: 11.2.5

PURPOSE
-------
Build the PoC from two blank Arista switches, then integrate them with
one Palo Alto Aggregate Ethernet (AE1).

The lab proves:

  1. Arista MLAG (vPC-like redundancy)
  2. VARP gateway on both Arista switches
  3. LACP from Palo Alto to both Arista peers
  4. Normal routing without the firewall in the path
  5. Selective PBR for one specific flow
  6. Reverse PBR for the selected return flow
  7. Palo Alto security-policy enforcement
  8. MLAG/LACP member failure and recovery

IMPORTANT
---------
This guide follows the SUCCESSFUL PoC design that was actually tested.

It intentionally uses:
  - VLAN 100 = INSIDE
  - VLAN 200 = OUTSIDE
  - PA ae1.100 = 10.100.100.254/24
  - PA ae1.200 = 10.200.200.254/24
  - Forward PBR next-hop = 10.100.100.254
  - Reverse PBR next-hop = 10.200.200.254

A later PoC can move to dedicated /30 transit VLANs. Do not change the
addressing in this guide when reproducing PoC-001.

PART 1 — ARISTA-01 CONFIGURATION FROM BLANK
================================================================

Enter enable/config mode:

  enable
  configure terminal

1. Enable routing:

  ip routing

2. Create VLANs:

  vlan 100
     name INSIDE

  vlan 200
     name OUTSIDE

  vlan 4094
     name MLAG-PEER
     trunk group MLAG-PEER

3. Build MLAG peer-link member interfaces:

  interface Ethernet1
     description MLAG PEER-LINK MEMBER 1
     channel-group 100 mode active
     exit

  interface Ethernet2
     description MLAG PEER-LINK MEMBER 2
     channel-group 100 mode active
     exit

4. Build the peer-link port-channel:

  interface Port-Channel100
     description MLAG PEER-LINK
     switchport mode trunk
     switchport trunk group MLAG-PEER
     exit

5. Build the MLAG local SVI:

  interface Vlan4094
     description MLAG LOCAL INTERFACE
     ip address 172.31.254.1/30
     no autostate
     exit

6. Disable STP for the dedicated MLAG control VLAN:

  no spanning-tree vlan-id 4094

7. Configure VLAN 100 SVI and VARP:

  interface Vlan100
     description INSIDE GATEWAY
     ip address 10.100.100.2/24
     ip address virtual 10.100.100.1/24
     exit

8. Configure VLAN 200 SVI and VARP:

  interface Vlan200
     description OUTSIDE GATEWAY
     ip address 10.200.200.2/24
     ip address virtual 10.200.200.1/24
     exit

9. Configure the common VARP virtual MAC:

  ip virtual-router mac-address 00:1c:73:00:99:99

10. Configure MLAG:

  mlag configuration
     domain-id MLAG-PALO-01
     local-interface Vlan4094
     peer-address 172.31.254.2
     peer-link Port-Channel100
     heartbeat-interval 2500
     exit

11. Build the MLAG downlink toward PA:

  interface Ethernet4
     description PA-AE1 MEMBER
     channel-group 20 mode active
     exit

  interface Port-Channel20
     description PA-AE1 MLAG DOWNLINK
     switchport mode trunk
     switchport trunk allowed vlan 100,200
     mlag 20
     exit

12. Build inside client ports:

  interface Ethernet5
     description MT-INSIDE-PBR
     switchport mode access
     switchport access vlan 100
     spanning-tree portfast
     exit

  interface Ethernet6
     description MT-INSIDE-NORMAL
     switchport mode access
     switchport access vlan 100
     spanning-tree portfast
     exit

13. Exit and save:

  end
  copy running-config startup-config

14. Verify:

  show ip interface brief
  show port-channel summary
  show mlag
  show mlag config-sanity
  show mlag interfaces

Expected:
  - Po100 up
  - MLAG peer active
  - Vlan4094 up
  - Vlan100 up
  - Vlan200 up
  - Po20 up/present
  - MLAG ID 20 present

PART 12 — CONFIGURE FORWARD PBR ON BOTH ARISTAS
================================================================

The selected flow is:

  source = 10.100.100.10
  destination = 10.200.200.10

The PBR next-hop is:

  10.100.100.254

This is the PA INSIDE subinterface.

The PBR chain on EOS is:

  ACL
    ->
  class-map type pbr
    ->
  policy-map type pbr
    ->
  set nexthop
    ->
  service-policy type pbr input

Why both Aristas?
-----------------
Either MLAG peer can route an ingress packet. The same PBR policy is
therefore configured on BOTH Arista switches.

ARISTA-01 + ARISTA-02:

1. ACL

  configure terminal

  ip access-list PBR-FWD
     10 permit ip host 10.100.100.10 host 10.200.200.10
     exit

2. Class map

  class-map type pbr match-any PBR-FWD-CMAP
     10 match ip access-group PBR-FWD
     exit

3. Policy map

  policy-map type pbr PBR-FWD-PMAP
     10 class PBR-FWD-CMAP
        set nexthop 10.100.100.254
        exit
     exit

4. Apply to VLAN 100 ingress:

  interface Vlan100
     service-policy type pbr input PBR-FWD-PMAP
     exit

5. Exit:

  end
  copy running-config startup-config

PART 18 — FAILURE / MLAG-LACP TEST
================================================================

This PoC also has a useful resilience test.

Before the test, start a continuous ping from the selected inside client:

  ping 10.200.200.10

Then on ARISTA-01:

  configure terminal
  interface Ethernet4
     shutdown
     exit
  end

This removes one PA AE1/MLAG member.

Expected behavior:
  - There may be a short convergence event
  - One or more ICMP sequences may be lost during convergence
  - Traffic should recover through ARISTA-02
  - PA AE1 should remain operational with the remaining member

Verify:

  show port-channel summary
  show lacp neighbor
  show mlag interfaces

Then restore:

  configure terminal
  interface Ethernet4
     no shutdown
     exit
  end

Verify LACP/MLAG returns to normal.

================================================================
KEY CONCEPTS TO REMEMBER
================================================================

1. MLAG
   Arista-01 and Arista-02 act as a redundant pair for the PA AE.

2. VARP
   Both Aristas can own the virtual gateway IP simultaneously.

3. LACP
   PA AE1 has two physical members:
     PA Eth1/1 -> ARISTA-01
     PA Eth1/2 -> ARISTA-02

4. PBR
   PBR is applied at ingress on the SVI where the packet enters the
   routing engine.

5. Selective PBR
   Only the exact .10 -> .10 flow is redirected.

6. Reverse PBR
   The return direction must also be redirected to the PA because the
   destination is behind the firewall insertion point.

7. Security Policy
   A session initiated from OUTSIDE is a new session and must be allowed
   by the Palo Alto security policy. That is why the tested lab rule has
   both INSIDE and OUTSIDE in Source Zone and Destination Zone.

8. Normal routing remains
   PBR does not remove the ordinary connected routes. Non-matching
   packets still use normal routing.
