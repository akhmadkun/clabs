LAB-002 - OSPF STUB AREAS, TOTALLY STUBBY, AND NSSA
ADDRESS PLAN AND LOGICAL VLAN MAPPING

PHYSICAL TOPOLOGY
The four cRPD routers use the same physical wiring pattern as LAB-001:
  R1 eth1 ----+
  R2 eth1 ----+---- existing host Linux bridge br-univ
  R3 eth1 ----+
  R4 eth1 ----+
The bridge is a shared Layer-2 broadcast domain. It is not an OSPF area.
The area membership is defined by tagged logical interfaces (802.1Q) on cRPD.
The topology diagram intentionally shows logical adjacencies, not br-univ.

ROUTER LOOPBACKS
  R1 lo0.0   10.1.1.1/32   Router ID to configure: 10.1.1.1
  R2 lo0.0   10.1.1.2/32   Router ID to configure: 10.1.1.2
  R3 lo0.0   10.1.1.3/32   Router ID to configure: 10.1.1.3
  R4 lo0.0   10.1.1.4/32   Router ID to configure: 10.1.1.4

LOGICAL OSPF LINKS
  Area 0 / VLAN 12:
    R1 eth1.12  10.0.12.1/24 <----> R2 eth1.12  10.0.12.2/24
    Default OSPF network type: broadcast. This link is used to review DR/BDR.

  Area 1 / VLAN 13:
    R1 eth1.13  10.0.13.1/24 <----> R3 eth1.13  10.0.13.3/24
    OSPF network type: point-to-point.
    This area changes through the lab: normal -> stub -> totally stubby -> NSSA
    -> NSSA with no-summaries (NSSA totally stubby behavior).

  Area 2 / VLAN 24:
    R2 eth1.24  10.0.24.2/24 <----> R4 eth1.24  10.0.24.4/24
    OSPF network type: point-to-point.

CONNECTED PREFIXES IN AREA 2
  R4 eth2.0  192.168.16.1/30 <----> EP16 eth1  192.168.16.2/30
  R4 eth3.0  192.168.17.1/24 <----> EP17 eth1  192.168.17.2/24
  R4 eth4.0  192.168.18.1/23 <----> EP18 eth1  192.168.18.2/23
  The R4 interfaces toward these hosts are to be passive in OSPF: advertise
  connected networks but do not attempt to form OSPF neighbors with the hosts.

EXTERNAL ROUTES ORIGINATED AT R4 FOR THE BASELINE
  192.168.29.0/24 via 192.168.16.2 (static, to be redistributed into OSPF)
  192.168.30.0/24 via 192.168.16.2 (static, to be redistributed into OSPF)
  These model external destinations from the example in Chapter 3. They are
  principally used to inspect Type-5 External LSAs and route suppression.
  End-to-end reachability to 192.168.29.0/24 and 192.168.30.0/24 is not an
  acceptance criterion because the endpoint does not host those destinations.

EXTERNAL ROUTES ORIGINATED AT R3 DURING THE NSSA EXERCISE
  192.168.71.0/24 discard
  192.168.72.0/24 discard
  These are synthetic static routes used instead of the book's RIP-connected
  R5. They are redistributed by R3 into Area 1 as Type-7 NSSA LSAs. R1, the
  ABR, should translate them into Type-5 External LSAs for the rest of OSPF.
  Because the next-hop is discard, these routes are for routing-protocol and
  LSA observation only, not for end-to-end application traffic.

CONTAINERLAB INTERFACE NOTES
  Official Containerlab cRPD mapping: eth0 is management; eth1 is the first
  data interface; eth2 and higher are subsequent data interfaces.
  The interface units eth1.12, eth1.13, and eth1.24 use VLAN tags 12, 13, 24.
  Startup configs contain interface addressing only. Router IDs, OSPF area
  types, route redistribution, and static test routes are configured manually.
