LAB-005 - MULTIPLE AUTONOMOUS SYSTEMS
ADDRESS PLAN AND LOGICAL VLAN MAPPING
Source: Day One: Advanced OSPF in the Enterprise, Chapter 6.

PHYSICAL CONNECTIVITY
  R1, R2, R3, R4, R6, R7, R8 and R9 each connect parent eth1 to the existing
  host bridge br-univ. VLAN subinterfaces on eth1 build logical links.
  R4 eth2/eth3/eth4 connect directly to EP16/EP17/EP18.
  R9 eth2/eth3 connect directly to EP91/EP92.
  The diagram intentionally omits br-univ and shows only logical links.

AUTONOMOUS SYSTEMS
  AS 65001: original network. OSPF process in inet.0 across R1-R4, plus the
             separate domain2 OSPF routing instance on R1 and R6-R7, with the
             Chapter 5 RIB-group and export-policy sharing configured at R1.
  AS 65002: separate OSPF network consisting of R8 and R9.
  eBGP:     R2 (AS 65001) <-> R8 (AS 65002) over VLAN 28.

EXPECTED ROUTE EXCHANGE
  Stage A: before redistribution, R2/R8 eBGP establishes but does not exchange
           OSPF routes by default.
  Stage B: R2 exports active AS 65001 OSPF routes to BGP; R8 receives BGP routes.
  Stage C: R8 exports active AS 65002 OSPF routes to BGP; R2 receives BGP routes.
  Stage D: BGP-to-OSPF export policies inject the other AS's BGP routes as
           Type-5 external LSAs. R4 and R9 should learn the remote LAN prefixes.
  Use show route protocol bgp, show route protocol ospf, show ospf route and
  show ospf database external to distinguish BGP RIB routes from OSPF externals.

ADDRESSING CONVENTIONS USED IN THIS LAB
  - Every router parent eth1 is connected to br-univ.
  - Logical p2p links use eth1.<VLAN>, the same VLAN ID at both ends, and /30.
  - For p2p subnets, the first endpoint uses .1 and the second uses .2.
  - The VLAN number is chosen to match the logical endpoint pair (for example,
    R1-R6 uses VLAN 16; R2-R8 uses VLAN 28; R8-R9 uses VLAN 89).
  - OSPF/BGP/instance/policy configuration is not in startup configs.
