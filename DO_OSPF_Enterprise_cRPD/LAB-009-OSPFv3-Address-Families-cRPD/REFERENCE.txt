LAB-009 - REFERENCES AND VERIFY COMMANDS

Primary source supplied for this roadmap:
Juniper Networks, Junos OS OSPF User Guide, June 18, 2026 edition.
Section: "Understanding Multiple Address Families for OSPFv3" and "Example: Configuring Multiple Address Families for OSPFv3", printed pages 41-47.

Source-supported details used in this lab:
- By default OSPFv3 supports IPv6 unicast.
- IPv4 unicast can be enabled as an additional realm using `realm ipv4-unicast`.
- Each address-family realm has a separate set of neighbors and link-state database.
- IPv6 unicast routes use inet6.0; IPv4 unicast routes use inet.0.
- OSPFv3 uses IPv6 link-local addresses as the source of Hello packets and next-hop calculations. IPv6 therefore must be enabled on a link even when configuring another realm.
- Juniper's example configures both `protocols ospf3 area ... interface ...` and `protocols ospf3 realm ipv4-unicast area ... interface ...` on a link.
- The guide specifically recommends `show ospf3 database realm ipv4-unicast` for the IPv4-unicast LSDB and `show ospf3 interface realm ipv4-unicast` to verify interface status in that realm.

Useful verification commands
  run show interfaces terse | match eth1
  run show configuration interfaces eth1 | display set
  run show configuration protocols ospf3 | display set
  run show ospf3 neighbor detail
  run show ospf3 interface detail
  run show ospf3 database
  run show ospf3 interface realm ipv4-unicast
  run show ospf3 database realm ipv4-unicast
  run show route table inet6.0 2001:db8:ffff::3/128 exact
  run show route table inet6.0 2001:db8:ffff::1/128 exact
  run show route table inet.0 10.1.1.3/32 exact
  run show route table inet.0 10.1.1.1/32 exact

Do not use successful commit alone as evidence of protocol success. Confirm neighbor state, realm/interface status, LSDB and installed routes. `ping` is not a required acceptance criterion for the cRPD CLI; route and OSPF state output is sufficient for this exercise.

LAB SERIES VLAN CONVENTION
For point-to-point logical links, the VLAN ID and Juniper unit number are the connected router pair: R1-R2 = 12 / eth1.12, R1-R3 = 13 / eth1.13, R2-R3 = 23 / eth1.23, R2-R4 = 24 / eth1.24. Endpoint IPv4 host octets are .1 on the lower-numbered router and .2 on the higher-numbered router when a /30 is used. A multi-access segment containing more than two routers is an explicit exception: assign one shared VLAN and document why the pair-based convention does not apply. Labs sharing br-univ must not be active concurrently if VLAN IDs overlap.
